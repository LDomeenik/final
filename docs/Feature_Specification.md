# 기능 명세서

```
본 문서는 서비스 기획서의 MVP 범위를 화면·API·배치 단위의 기능으로 나누어,
각 기능의 동작 흐름, 입력, 처리 규칙, 출력, 예외 처리를 정의합니다.

테이블과 컬럼 정의는 데이터 명세서를 따르며,
본 문서는 "사용자가 무엇을 하면 서비스가 어떻게 동작하는가"를 기준으로 작성합니다.
API 명세와 화면 설계는 본 문서의 기능 ID를 기준으로 작성합니다.
```

**작성 기준**

- **기능 ID**: `영역코드-번호` (예: INV-01)

| 영역코드 | 영역 |
| :--- | --- |
| AUTH | 회원·프로필 |
| INV | 재고 관리 |
| REC | 레시피·추천 |
| RPT | 식비·폐기 분석 |
| SCR | 점수·뱃지 |
| COM | 커뮤니티 |
| NOTI | 알림 |
| ADM | 관리자·데이터 적재 |
| BAT | 배치 |

- **우선순위**

| 우선순위 | 의미 |
| :--- | --- |
| P0 | 핵심 흐름. 이것만으로 "시작 화면 체험 → 가입 → 캡처 → 재고 → 추천 → 완료 → 점수"가 동작해야 함 |
| P1 | MVP 범위. P0 완성 후 구현 |
| P2 | 확장 기능. 문서 마지막에 목록만 정리 |

- **공통 규칙**
  - 로그인이 필요한 기능은 토큰이 없거나 유효하지 않으면 401을 반환하고 로그인 화면으로 이동
  - **비회원 허용 기능**: 아래 기능만 로그인 없이 사용할 수 있으며, 나머지는 모두 로그인 필요
    - REC-07 비회원 재료로 레시피 보기 (재료 선택, 레시피 결과)
    - REC-03 레시피 상세 (열람만, 요리 완료는 가입 후)
    - AUTH-01 회원가입, AUTH-02 로그인
  - 비회원 기능은 LLM을 호출하지 않음 (키워드 매칭만 사용해 비용이 들지 않게 함)
  - 다른 사용자의 재고·캡처·추천 기록에는 접근할 수 없음 (본인 데이터만 조회·수정, 위반 시 404)
  - 날짜·주·시간대는 모두 한국 시간(Asia/Seoul) 기준이며, 한 주는 월요일 00:00 ~ 일요일 23:59
  - 금액은 원 단위 정수, 소비기한은 "예상 소비기한"으로 표시
  - 재고·점수 이력은 삭제하지 않고 이벤트로 기록 (취소도 이벤트)
  - 화면은 데스크톱 우선으로 설계 (화면 설계 문서 기준, 모바일 대응은 확장)

## 2. 회원·프로필 (AUTH)

### AUTH-01 회원가입 `P0`

- **설명**: 이메일과 비밀번호로 가입하고 닉네임을 정한다.
- **진입 경로**: 시작 화면의 가입 버튼, 또는 비회원이 저장·캡처 등록·요리 완료를 시도할 때 뜨는 가입 안내 창
- **입력**
  - 필수: 이메일, 비밀번호, 비밀번호 확인, 닉네임
  - 선택: 활동 지역(시·도 → 시·군·구 선택), 가구 인원, 선호 요리 종류(밥 · 국·찌개 · 반찬 · 일품 · 후식 중 다중 선택, 공공 레시피의 요리 종류와 같은 값)
- **처리 규칙**
  - 이메일 형식 검사, 이메일·닉네임 중복 검사 (입력 중 중복 확인 API 제공)
  - 닉네임 2~20자, 비밀번호는 Django 기본 비밀번호 검증 규칙 적용
  - 가입 즉시 로그인 상태로 전환
  - **비회원 선택 재료 옮기기**: 시작 화면에서 고른 재료(브라우저 임시 저장)가 있으면, 가입 직후 "고른 재료 N개를 냉장고에 넣을까요?" 안내 → 수락 시 INV-03 일괄 추가 화면으로 이동해 재료별 표준 재료·수량을 확인하고 저장, 거절하거나 저장하면 임시 저장 값은 삭제
- **출력**: 사용자 정보와 인증 토큰
- **예외**
  - 이메일·닉네임 중복 → 해당 필드에 오류 메시지
  - 비밀번호 불일치·규칙 위반 → 해당 필드에 오류 메시지

### AUTH-02 로그인·로그아웃 `P0`

- **설명**: 이메일·비밀번호로 로그인하고 토큰을 발급받는다.
- **처리 규칙**
  - 로그인 성공 시 last_login 갱신, 토큰 발급
  - 로그인 후 홈으로 이동하고, 조건이 맞으면 오늘의 냉장고 카드(REC-02) 표시
  - 로그아웃 시 토큰 폐기 후 시작 화면으로 이동
  - 탈퇴한 사용자(is_active = FALSE)는 로그인 불가
- **출력**: 인증 토큰, 내 정보(닉네임, 프로필 이미지, 활동 지역)
- **예외**: 이메일 또는 비밀번호 불일치 → "이메일 또는 비밀번호를 확인해 주세요" (어느 쪽이 틀렸는지 구분하지 않음)

### AUTH-03 내 정보·프로필 수정 `P1`

- **설명**: 프로필 정보와 비밀번호를 수정한다.
- **입력**: 닉네임, 프로필 이미지, 한 줄 소개, 가구 인원, 선호 요리 종류(다중 선택), 활동 지역, 공개 여부 / 비밀번호 변경 시 현재 비밀번호와 새 비밀번호
- **처리 규칙**
  - 프로필 이미지는 jpg·png·webp, 5MB 이하, 외부 스토리지에 저장
  - 닉네임 변경 시 중복 검사
  - 비공개로 바꾸면 피드 게시글과 점수는 팔로워에게만 노출
- **예외**: 현재 비밀번호 불일치 → 변경 거부

### AUTH-04 회원 탈퇴 `P1`

- **설명**: 계정을 비활성화한다.
- **처리 규칙**
  - 비밀번호 재확인 후 진행
  - is_active = FALSE, withdrawn_at 기록, 닉네임 "탈퇴한 사용자#{id}", 이메일·프로필 이미지·소개 삭제
  - 작성한 게시글·댓글은 남기고 작성자는 익명으로 표시
  - 진행 중인 나눔 글(나눔중·예약중)은 자동으로 삭제 처리
  - 토큰 폐기 후 시작 화면으로 이동

### AUTH-05 사용자 프로필 페이지 `P1`

- **설명**: 사용자의 공개 정보와 활동을 보여준다. 내 프로필은 마이페이지에서 같은 화면에 점수 내역 탭을 더해 보여준다.
- **출력**: 닉네임, 프로필 이미지, 한 줄 소개, 활동 지역, 이번 주 점수, 획득 뱃지(뱃지별 횟수), 팔로워·팔로잉 수, 게시글 목록(피드 / 나눔 탭), 팔로우 버튼
- **처리 규칙**
  - 비공개 사용자이고 내가 팔로워가 아니면 점수와 피드 게시글은 숨기고 나눔 글만 표시
  - 탈퇴한 사용자의 프로필은 "탈퇴한 사용자입니다"로 표시

## 3. 재고 관리 (INV)

### INV-01 캡처 업로드·인식 `P0`

- **설명**: 결제내역 캡처 이미지를 업로드하면 비전 LLM이 품목, 수량, 가격, 구매일을 추출한다.
- **흐름**
  1. 사용자가 냉장고 화면의 "캡처 불러오기"로 이미지 선택 (1회 1장)
  2. 서버가 이미지를 저장하고 capture 생성 (status = uploaded)
  3. 비전 LLM 호출 → 구조화 결과(JSON)를 capture_item.predicted_*에 저장, 상품명은 product_alias로 1차 정규화 (status = recognized)
  4. 확인 화면(INV-02)으로 이동
- **입력**: 이미지 (jpg·png·webp, 10MB 이하)
- **처리 규칙**
  - 인식 대상: 구매처, 구매일, 품목별 상품명·수량 원문·품목 금액, 주문 단위 할인·배송비·총 결제 금액
  - 식재료가 아닌 상품(세제, 휴지 등)은 LLM이 is_food = false로 표시하고, 확인 화면에서 기본으로 제외 상태로 보여줌
  - LLM 응답 원본, 모델명, 프롬프트 버전 저장
  - 인식 중에는 로딩 화면 표시 (목표 응답 시간 10초 이내)
- **출력**: capture_id, 인식된 품목 목록
- **예외**
  - 형식·용량 위반 → 업로드 거부
  - LLM 호출 실패·시간 초과 → status = failed, "다시 시도" 버튼 (이미지는 보존하여 재처리)
  - 품목을 하나도 찾지 못함 → "결제내역을 찾지 못했어요" 안내와 직접 추가(INV-03) 버튼

### INV-02 인식 결과 확인·재고 저장 `P0`

- **설명**: 인식 결과를 사용자가 확인·수정한 뒤 재고로 저장한다.
- **화면 구성**: 품목별로 표준 재료, 수량·단위, 가격, 보관 위치, 제외 여부 / 상단에 구매처, 구매일, 할인, 배송비
- **처리 규칙**
  - 표준 재료는 자동완성으로 변경 가능, 정규화에 실패한 품목은 "재료를 선택해 주세요"로 표시하고 저장 전 필수 선택
  - 보관 위치 기본값은 ingredient.default_storage
  - 품목 금액 합계 - 할인 + 배송비가 총 결제 금액과 다르면 "누락된 품목이 있을 수 있어요" 경고 (저장은 가능)
  - 저장 시
    - capture_item.confirmed_* 기록, capture.status = confirmed
    - 제외하지 않은 품목마다 inventory_item 생성 (예상 소비기한 = 구매일 + 보관 위치별 일수), inventory_event(created) 기록
    - 확정된 상품명 → 표준 재료 매핑을 product_alias에 누적 (source = user, confirmed_count 증가)
    - 첫 캡처 저장이면 first_capture 뱃지 판정 (SCR-03)
- **출력**: 등록된 재고 목록, 가장 임박한 재료 안내 → 냉장고 화면으로 이동 (새 재료가 그림에 들어가는 효과)
- **예외**: 구매일 인식 실패 → 오늘 날짜를 기본값으로 채우고 수정 가능

### INV-03 재료 직접 추가 `P0`

- **설명**: 캡처 없이 재료를 추가한다. 한 번에 여러 건(최대 20건)을 추가할 수 있다.
- **진입 경로**: 냉장고 화면의 "재료 넣기", 가입 직후 비회원 선택 재료 옮기기(AUTH-01)
- **입력 (재료별)**
  - 필수: 표준 재료(자동완성), 수량(count·amount 재료), 구매일(기본 오늘), 보관 위치(기본값 자동)
  - 선택: 가격
- **처리 규칙**
  - presence 재료(양념 등)는 수량 입력 없이 "있음"으로 등록
  - 가격 미입력 시 purchase_price = NULL (식비 집계에서 제외하고 "가격 미입력"으로 별도 표시)
  - 비회원 선택 재료는 재료 그룹 단위이므로, 그룹에 표준 재료가 하나면 자동 선택하고 여러 개면(예: 우유 / 저지방우유) 사용자가 선택
  - 재료마다 inventory_item 생성, inventory_event(created) 기록 (일괄 저장은 하나의 트랜잭션, 한 건이라도 오류면 전체 저장 안 함)
- **예외**: 기준 테이블에 없는 재료 → "목록에 없는 재료예요" 안내 (MVP에서는 기준 테이블에 있는 재료만 등록 가능, 관리자에게 추가 요청은 확장)

### INV-04 냉장고 (재고 목록) 조회 `P0`

- **설명**: 내 재료를 냉장고 그림 안에 배치해 보여주고, 임박 재료를 함께 보여준다.
- **화면 구성**
  - 냉장고 그림: 냉동칸 · 냉장 선반 · 채소칸 · 도어 · 실온 선반으로 나누고 칸마다 재료 그림(아이콘)을 배치
  - 재료 그림마다 남은 일수 배지(D-3, D-day, 기한 지남)와 수량 표시(개수 / 많음·반쯤·조금 / 있음)
  - 같은 표준 재료가 같은 칸에 있으면 그림 하나로 묶고(보관 위치가 다르면 각 칸에 따로), 누르면 상세 패널(INV-05)에서 구매 건(lot)별로 표시
  - 필터: 전체 / 냉장 / 냉동 / 실온 (선택한 보관 위치의 칸을 강조), 임박 재료 목록은 임박순 정렬
  - 상단 요약: 임박 재료 수(남은 일수 3일 이하), 기한 경과 확인 필요 수, 버튼(캡처 불러오기, 재료 넣기)
- **처리 규칙**
  - status = active인 재고만 표시, 다 씀·버림·나눔 처리되면 그림에서 빠지고 새로 등록하면 들어감
  - 칸 배치는 화면 표시용이며 DB에는 storage(fridge / freezer / room)만 저장
    - freezer → 냉동칸, room → 실온 선반
    - fridge → 재료 그룹 분류(ingredient_group.category)로 나눔: 채소·과일 → 채소칸, 음료·소스·양념 → 도어, 나머지 → 냉장 선반
  - 칸별 재료가 많으면 일부만 보여주고 "더 보기"로 펼침
  - P0에서는 재료를 눌러 상세 패널(INV-05)에서 보관 위치를 바꾸고, 그림에서 끌어서 옮기는 동작은 INV-09(P1)에서 추가
- **예외**: 재고 없음 → 빈 냉장고 그림과 "캡처 한 장으로 재료를 등록해 보세요" 안내, 업로드 버튼

### INV-05 재고 상세·수정 `P0`

- **설명**: 재고 한 건의 정보를 보고 보관 상태와 수량을 수정한다. (냉장고 화면의 상세 패널)
- **기능**
  - 보관 위치 변경 ("옮기기"): 예상 소비기한 = 변경일 + 새 보관 위치 일수 (storage_changed)
    - 구매 건을 통째로 옮기기 (P0)
    - 일부 수량만 옮기기 = 소분 (P1): 예) 돼지고기 500g 중 200g만 냉동
      - 원래 건의 수량·구매 가격을 줄이고, 옮긴 만큼 새 재고를 만듦 (새 건 가격 = 원래 가격 × 옮긴 수량 / 원래 처음 수량, 두 건의 가격 합은 원래 가격과 같음)
      - 새 건은 구매일이 같고 소비기한만 새로 계산, 어느 건에서 나왔는지 기록 (split 이벤트)
      - 다시 같은 칸으로 옮겨도 두 건을 합치지 않음 (화면에서는 같은 재료로 묶여 보임)
      - presence 재료는 통째로만 옮길 수 있음
  - 개봉 처리: 예상 소비기한 = MIN(현재 값, 개봉일 + opened_days) (opened)
  - 남은 양 수정: 개수 입력 또는 많음·반쯤·조금 선택 → 차이만큼 adjusted 이벤트
    - 단계는 처음 양의 80% / 50% / 20%로 저장, 이미 그 단계 안이면 바꾸지 않음
    - 줄어들면 value_delta를 소진 금액으로 기록
    - 늘리는 것도 가능 (처음 양까지): 늘어난 만큼 value_delta를 마이너스로 기록해 앞선 소진 기록을 바로잡음, 점수에는 영향 없음
  - 소비기한 직접 수정: expiry_source = manual, 이후 자동 재계산 제외
  - 변경 이력 보기: inventory_event 목록
  - 바로가기: "이 재료로 뭐 만들지?"(REC-06), "나눔하기"(COM-06), "다 씀 / 버림"(INV-06)
- **예외**: 해당 보관 방식의 일수가 NULL인 재료(예: 계란 냉동) → 해당 보관 위치 선택 불가 안내

### INV-06 다 씀·버림 처리 `P0`

- **설명**: 레시피 밖에서 재료를 다 쓰거나 버린 경우 처리한다.
- **처리 규칙**
  - 다 씀: inventory_event(used_up), 남은 수량 0, status = used_up
  - 버림: inventory_event(discarded), status = discarded
  - value_delta = 남은 가치 (presence 재료는 구매 가격 전액)
  - 이벤트 저장과 같은 트랜잭션에서 점수 반영 (SCR-01)
- **출력**: 처리 결과, 점수 변화("+3점 · 재료 다 씀" / "-5점 · 3,200원어치 폐기"), 취소 버튼

### INV-07 처리 취소 `P1`

- **설명**: 잘못 누른 다 씀·버림·수량 수정·레시피 완료를 되돌린다.
- **처리 규칙**
  - 처리 후 24시간 이내의 이벤트만 취소 가능
  - 원래 이벤트의 수량·금액을 반대 부호로 기록한 reverted 이벤트 생성, 재고 상태 복원
  - 연결된 점수 이벤트도 반대 점수로 기록 (SCR-01)
  - 레시피 완료 취소는 해당 완료의 consumed 이벤트를 모두 한 번에 취소
  - 보관 위치 변경·소분은 취소 대상이 아님 (다시 옮기면 됨)
- **예외**: 24시간 경과, 이미 취소된 이벤트, 이후에 다른 처리가 있는 재고 → 취소 불가 안내

### INV-08 기한 경과 확인 ("아직 있나요?") `P1`

- **설명**: 예상 소비기한이 지난 재료가 아직 있는지 확인해 상태를 바로잡는다.
- **흐름**: BAT-02가 알림을 만들고, 사용자가 알림이나 냉장고 화면의 "확인 필요" 배지에서 응답
- **응답별 처리**
  - 아직 있어요: check_response(still_have), last_checked_at 갱신, 방치 감점 중단, 3일 뒤 다시 확인
  - 다 먹었어요: check_response(used_up) + used_up 이벤트
  - 버렸어요: check_response(discarded) + discarded 이벤트
- **처리 규칙**: 다 먹었어요·버렸어요는 INV-06과 같은 금액·점수 규칙 적용

### INV-09 냉장고 그림 드래그 이동 `P1`

- **설명**: 냉장고 그림에서 재료를 끌어 다른 칸에 놓는다. 보관 위치가 바뀌는 이동만 저장한다.
- **보관 위치가 바뀌는 이동** (냉장 ↔ 냉동 ↔ 실온)
  - 놓는 순간 확인 창: "냉동으로 보관 위치를 바꾸시겠습니까? 예상 소비기한이 11/30 → 12/28로 바뀌어요"
  - 묶인 재료(구매 건이 여러 개)를 끌면 확인 창에 구매 건 목록을 보여주고 소비기한이 빠른 건을 기본 체크, 옮길 건을 고를 수 있음
  - 건마다 "전부 / 일부"를 고르고, 일부면 수량 입력 (개수 재료는 개수, 양 재료는 g·ml 또는 "절반" 버튼) → INV-05의 소분 규칙 적용
  - 확인: INV-05의 보관 위치 변경과 같은 처리 (storage 변경, 예상 소비기한 재계산, storage_changed·split 이벤트)
  - 취소: 재료가 원래 칸으로 돌아감
  - 소비기한을 직접 수정한 재료(expiry_source = manual)는 날짜를 바꾸지 않고 확인 창에 "소비기한은 그대로예요" 표시
- **냉장고 안에서 칸만 바뀌는 이동** (냉장 선반 ↔ 채소칸 ↔ 도어)
  - DB에 저장하지 않고 화면에서만 옮겨 둠, 새로고침하면 자동 배치(INV-04)로 돌아감
- **예외**: 해당 보관 방식의 일수가 NULL인 재료(예: 계란 냉동) → "이 재료는 냉동 보관할 수 없어요" 안내 후 원래 칸으로 되돌림

## 4. 레시피·추천 (REC)

### REC-01 RAG 레시피 추천 `P0`

- **설명**: 임박 재료와 보유 재료를 바탕으로 실제 레시피 중에서 추천하고 이유를 설명한다.
- **흐름**
  1. 입력 스냅샷 생성: 임박 재료(남은 일수 3일 이하), 보유 재료 그룹, 최근 완료 레시피 5개, 선호 요리 종류, 현재 시간대
  2. 캐시 확인: 같은 날 같은 재고 조합 해시의 성공 요청이 있으면 결과 재사용
  3. 검색: 임베딩 유사도 + 재료명 키워드 일치로 후보 20~30개 (is_recommendable = TRUE, is_active = TRUE만)
  4. 생성: LLM이 후보 중 5개를 고르고 추천 이유, 사용될 임박 재료, 대체 재료 제안을 JSON으로 반환
  5. 검증: 후보 밖 recipe_id 제외, 유효 항목이 없으면 검색 상위 5개로 대체 (status = fallback)
  6. 저장: recommendation_request, recommendation_impression
- **출력**: 레시피 카드 5개 (대표 이미지, 메뉴명, 추천 이유 한 줄, "임박 재료 2개 사용", "재료 5개 중 4개 보유")
- **처리 규칙**
  - 임박 재료가 없으면 보유 재료 기준으로 추천
  - 시간대는 요리 종류 가중치와 프롬프트로만 반영 (강한 필터 아님)
  - 새로고침 시 캐시를 쓰지 않고 이전에 보여준 레시피는 후순위로 둠 (trigger = refresh)
- **예외**
  - 재고가 하나도 없음 → 시간대에 맞는 공공 레시피를 보여주고 "재료를 등록하면 맞춤 추천을 받을 수 있어요" 안내
  - LLM과 검색 모두 실패 → "추천을 불러오지 못했어요" 안내와 레시피 검색(REC-04) 버튼

### REC-02 오늘의 냉장고 카드 `P1`

- **설명**: 접속 시 오늘의 재고 상태와 지금 시간대에 맞는 레시피 1개를 카드로 보여준다.
- **표시 조건**
  - 로그인 후 홈 진입 시, 현재 시간대에 trigger = welcome 요청이 오늘 없고 오늘 dismissed가 없을 때만 표시
  - 시간대: 아침 05~10시 / 점심 10~14시 / 간식 14~17시, 22~05시 / 저녁 17~22시
- **화면 구성** (홈 위에 뜨는 모달)
  - 재고 상태(즉시 표시): 임박 재료 수와 이름 최대 3개, 기한 경과 확인 필요 수, 이번 주 점수
  - 추천 레시피(로딩 후 표시): REC-01과 같은 흐름으로 1개, 추천 이유, "레시피 보기", "다른 추천 보기"
  - 닫기, "오늘은 그만 보기"
- **처리 규칙**
  - 추천 요청은 trigger = welcome, meal_slot과 함께 기록
  - "다른 추천 보기"는 같은 요청의 다음 순위 후보를 보여줌 (추가 LLM 호출 없음)
  - "오늘은 그만 보기" → dismissed = TRUE, 그날은 다시 표시하지 않음

### REC-03 레시피 상세 `P0`

- **설명**: 레시피의 재료와 조리 순서를 보여주고 완료 체크로 연결한다. 비회원도 열람할 수 있다.
- **화면 구성**
  - 대표 이미지, 메뉴명, 요리 종류, 기준 인분, 출처(공공 레시피 / 작성자 닉네임)
  - 재료 목록: 재료명, 분량 텍스트, 보유 여부 표시(보유 / 임박 / 없음)
  - 조리 순서: 단계별 텍스트와 이미지
  - 조리 팁, 추천에서 들어온 경우 추천 이유
  - "요리 완료" 버튼(REC-05), 사용자 레시피는 원본 피드 게시글 링크
- **처리 규칙**
  - 추천을 통해 열면 recommendation_impression.is_clicked = TRUE
  - 비회원: 보유 여부는 시작 화면에서 고른 재료 그룹 기준으로 "있음 / 없음"만 표시 (임박 표시 없음), "요리 완료"를 누르면 가입 안내 창
- **예외**: 비활성화된 레시피 → "삭제된 레시피예요" (완료 기록에서 들어온 경우 내용은 표시)

### REC-04 레시피 검색 `P1`

- **설명**: 메뉴명이나 재료명으로 레시피를 찾는다.
- **입력**: 검색어, 요리 종류 필터, 출처 필터(전체 / 공공 / 사용자)
- **처리 규칙**
  - 메뉴명 부분 일치 + 레시피 재료명 일치로 검색
  - 결과마다 "재료 N개 중 M개 보유" 표시, 보유 비율 높은 순 정렬 옵션
- **예외**: 결과 없음 → "검색 결과가 없어요"

### REC-05 레시피 완료 체크·재고 차감 `P0`

- **설명**: 요리를 마치면 사용한 재료를 골라 재고를 차감하고 점수를 반영한다.
- **흐름**
  1. 레시피 상세에서 "요리 완료" 선택
  2. 완료 확인 화면: 레시피 재료 중 보유한 재료만 표시, 같은 재료 그룹 재고가 여러 건이면 소비기한이 빠른 것을 기본 선택 (다른 lot으로 변경 가능), 추천에서 들어온 경우 LLM이 제시한 사용 재료를 기본 선택
  3. 재료별 사용량 선택
     - 양으로 관리하는 재료: 다 씀 / 절반 / 조금 / 안 씀 (현재 남은 양의 100% / 50% / 25% / 0%)
     - 개수로 관리하는 재료: 사용 개수 입력 (기본 1)
     - presence 재료: 표시만 하고 차감 없음
     - 레시피에 없지만 함께 쓴 재료: "재료 추가"로 재고에서 선택
  4. 저장
- **처리 규칙**
  - recipe_completion 생성 (impression_id는 추천에서 들어온 경우 연결)
  - 재료별 inventory_event(consumed, usage_level, days_left, value_delta) 생성, 남은 수량이 0이면 status = used_up
  - used_value, expiring_used_cnt 요약 저장
  - 점수 반영 (SCR-01)
- **출력**: "임박 재료 2개 · 4,800원어치 소진 · +8점", "피드에 자랑하기" 버튼(COM-02, 완료 기록 자동 연결), 취소 버튼(INV-07)
- **예외**: 보유 재료가 하나도 없음 → 재고 차감 없이 완료 기록만 저장할지 확인

### REC-06 특정 재료로 추천 `P1`

- **설명**: 재고 상세에서 선택한 재료를 반드시 사용하는 레시피를 추천한다.
- **처리 규칙**: REC-01과 같은 흐름이며, 선택한 재료의 재료 그룹을 포함한 레시피만 후보로 검색 (trigger = ingredient)
- **예외**: 해당 재료를 쓰는 레시피가 없음 → "이 재료를 쓰는 레시피를 찾지 못했어요"

### REC-07 비회원 재료로 레시피 보기 `P0`

- **설명**: 가입하지 않은 방문자가 시작 화면에서 가진 재료를 고르면, 그 재료로 만들 수 있는 레시피를 바로 보여준다. (레이지 등록의 첫 단계)
- **흐름**
  1. 시작 화면에서 재료 칩 선택 (자주 쓰는 재료 그룹 칩 + 재료명 검색)
  2. "레시피 보기" → 레시피 결과 목록
  3. 결과 카드에서 레시피 상세(REC-03, 비회원 열람)로 이동
  4. 저장·캡처 등록·요리 완료를 시도하면 가입 안내 창 → 회원가입(AUTH-01)
- **입력**: 재료 그룹 1~10개
- **처리 규칙**
  - 재료 칩은 재료 그룹 단위 (자주 쓰는 그룹 20개 안팎을 기본 칩으로 노출, 나머지는 검색)
  - 검색: 선택한 재료 그룹을 포함한 레시피를 recipe_ingredient 키워드 매칭으로 찾음 (LLM·임베딩 호출 없음, is_active = TRUE인 공공 레시피만)
  - 정렬: 선택 재료와 겹치는 수가 많은 순 → 양념 제외 부족 재료가 적은 순
  - 결과 카드: 대표 이미지, 메뉴명, 요리 종류, "고른 재료 3개 사용", "부족한 재료 2개"
  - 결과는 한 페이지 12개, 페이지 번호로 이동
  - 고른 재료는 브라우저에 임시 저장 (새로고침해도 유지), 가입 직후 냉장고로 옮기기 안내 (AUTH-01)
  - 비회원 요청은 기록(recommendation_request 등)을 남기지 않음, 과도한 호출은 IP 기준으로 제한
- **출력**: 레시피 결과 목록, 기능 소개 영역(캡처 등록·맞춤 추천·점수), 가입 안내
- **예외**
  - 재료를 하나도 고르지 않음 → "레시피 보기" 비활성화
  - 결과 없음 → "이 재료 조합으로는 레시피를 찾지 못했어요. 재료를 하나 빼 보세요"

## 5. 식비·폐기 분석 (RPT)

### RPT-01 오늘의 변화 `P1`

- **설명**: 홈 화면에 오늘 아낀 금액, 버린 금액, 점수 변화를 보여준다.
- **출력**: 오늘 소진 금액(그중 임박 재료 소진 금액), 폐기 금액, 나눔 금액, 점수 변화 합계
- **처리 규칙**: vw_daily_summary 기준, 취소된 처리는 자동 반영

### RPT-02 주간 리포트 `P1`

- **설명**: 이번 주(또는 지난주)의 식비와 낭비를 요약한다.
- **출력**
  - 구매 금액(할인·배송비 별도), 소진·폐기·나눔 금액, 폐기 비율
  - 자주 버린 재료 상위 3개, 지난주 대비 폐기 금액·구매 금액 변화
  - 주간 점수와 요일별 추이(SCR-02)
- **처리 규칙**: 주 선택(이전 주 이동) 가능, 지난주 리포트는 월요일 배치 후 알림(BAT-03)
- **예외**: 데이터 없음 → "이번 주 기록이 아직 없어요"

### RPT-03 월간 가계부 `P1`

- **설명**: 월별 식비와 폐기 금액을 가계부 형태로 보여준다 (리포트 화면의 보조 탭).
- **출력**: 품목 구매 금액, 주문 할인, 배송비, 실 지출 식비, 폐기 금액, 구매 품목 수, 가격 미입력 품목 수
- **처리 규칙**: 월 선택 가능, vw_monthly_ledger 기준

## 6. 점수·뱃지 (SCR)

### SCR-01 점수 반영·즉시 피드백 `P0`

- **설명**: 재고 이벤트가 생길 때마다 점수 규칙을 적용하고 결과를 바로 보여준다.
- **점수 대상 이벤트**

| 규칙 코드 | 발생 시점 | 방향 |
| :--- | --- | :---: |
| expiring_used | 남은 일수 3일 이하 재료를 레시피 완료·다 씀으로 소진 | + (남은 일수가 적을수록 가중) |
| used_up | 재료 다 씀 (임박이 아닌 경우, 요리 완료로 남은 수량이 0이 된 경우 포함) | + |
| shared_done | 나눔 완료 | + |
| discarded | 폐기 | − (폐기 금액 비례) |
| neglected | 기한 경과 후 미확인 (BAT-02) | − (일 단위, 재료 1건당 최대 3일) |

- **처리 규칙**
  - 이벤트 저장과 같은 트랜잭션에서 score_event 생성, weekly_score.current_score 갱신 (이번 주 행이 없으면 기본 50점으로 생성)
  - 하루 가점 합계가 상한을 넘으면 넘는 만큼 잘라서 기록 (사유에 "오늘 가점 상한 도달" 표시)
  - 처리 취소(INV-07) 시 반대 점수 이벤트 기록
  - 점수 값은 score_rule에서 읽음 (ADM-04에서 조정)
- **출력**: 해당 API 응답에 점수 변화량, 사유, 현재 점수를 포함 → 화면에 토스트와 게이지 애니메이션

### SCR-02 점수 게이지·요일별 추이 `P1`

- **설명**: 홈 화면에 이번 주 점수 게이지와 요일별 변화를 보여준다.
- **출력**: 현재 점수(게이지는 0~100으로 표시, 100 초과 시 "만점 달성"), 요일별 누적 점수 그래프, 최근 점수 이벤트 5개(사유·점수)
- **처리 규칙**: 점수 이벤트 전체 목록은 마이페이지의 "점수 내역"에서 확인

### SCR-03 뱃지 `P1`

- **설명**: 달성 조건을 채우면 뱃지를 부여하고 프로필에 표시한다.
- **초기 뱃지**

| 코드 | 이름 | 종류 | 판정 시점 |
| :--- | --- | --- | --- |
| weekly_zero_waste | 이번 주 폐기 0원 | 주간 | 월요일 배치 (그 주 재고 이벤트가 1건 이상일 때만) |
| weekly_all_expiring_used | 임박 재료 모두 소진 | 주간 | 월요일 배치 |
| streak_80_3weeks | 3주 연속 80점 이상 | 연속 | 월요일 배치 |
| first_capture | 첫 캡처 등록 | 첫 달성 | INV-02 저장 시 |
| first_share | 첫 나눔 완료 | 첫 달성 | COM-06 완료 시 |

- **처리 규칙**
  - 주간·연속 뱃지는 주마다 다시 받을 수 있고, 프로필에는 횟수로 표시 (예: ×3)
  - 획득 시 알림 생성 (NOTI-01)
  - 뱃지 목록 화면: 획득한 뱃지와 아직 못 받은 뱃지(조건 설명) 표시

## 7. 커뮤니티 (COM)

### COM-01 피드 목록 `P1`

- **설명**: 인스타그램형 카드 피드로 요리 자랑과 레시피 공유 글을 보여준다.
- **화면 구성**
  - 범위: 전체 / 팔로잉
  - 탭: 전체 / 자랑 / 레시피
  - 카드: 작성자, 대표 사진, 본문 일부, 소진 배지("임박 재료 2개 · 4,800원어치 소진"), 좋아요 수, 댓글 수, 작성 시각
- **처리 규칙**
  - 최신순, 무한 스크롤 (커서 기반 페이지네이션, 1회 10개)
  - 삭제된 글 제외, 비공개 사용자의 글은 팔로워와 본인에게만 표시

### COM-02 자랑 글 작성·수정·삭제 `P1`

- **설명**: 내가 만든 요리를 사진과 함께 올린다.
- **입력**
  - 필수: 사진 1~5장, 본문
  - 선택: 요리 완료 기록 연결 (최근 7일 내 내 완료 기록 중 선택, REC-05에서 "피드에 자랑하기"로 들어오면 자동 연결)
- **처리 규칙**
  - post(board = feed) + feed_detail(feed_type = brag) 생성
  - 완료 기록을 연결하면 recipe_id 자동 설정, 카드에 소진 배지와 레시피 링크 표시
  - 수정: 본문, 사진 변경 가능 (완료 기록 연결은 변경 불가)
  - 삭제: 소프트 삭제
- **예외**: 사진 없음 → 작성 불가

### COM-03 레시피 공유 글 작성·수정·삭제 `P1`

- **설명**: 직접 만든 레시피를 구조화해서 공유한다.
- **입력**
  - 필수: 메뉴명, 대표 사진, 기준 인분, 재료 1개 이상(재료명 + 분량 텍스트), 조리 단계 1개 이상(텍스트)
  - 선택: 요리 종류, 단계별 사진(단계당 1장), 본문(소개)
- **처리 규칙**
  - 재료명은 자동완성으로 재료 그룹에 연결, 목록에 없는 재료는 그룹 없이 저장 (match_source = user)
  - recipe(source = user, author_id, is_recommendable = FALSE) + recipe_ingredient 생성
  - post(board = feed) + feed_detail(feed_type = recipe, recipe_id) 생성
  - 수정: 작성자만 가능, 이미 다른 사용자가 완료한 기록은 그대로 유지
  - 삭제: 게시글 소프트 삭제 + 레시피 is_active = FALSE
- **출력**: 다른 사용자도 이 레시피로 REC-03 상세 보기와 REC-05 완료 체크 가능

### COM-04 게시글 상세 `P1`

- **설명**: 피드·나눔 게시글의 상세 내용과 댓글을 보여준다.
- **출력**: 작성자, 이미지(슬라이드), 본문, 게시판별 정보(피드: 소진 배지·레시피 / 나눔: 제목·지역·거래 상태), 반응 수와 내 반응 여부, 댓글 목록
- **처리 규칙**: 작성자에게만 수정·삭제 버튼, 나눔 글 작성자에게는 거래 상태 변경 버튼
- **예외**: 삭제된 글 → "삭제된 게시글이에요"

### COM-05 나눔 게시판 목록 `P1`

- **설명**: 당근마켓형 리스트로 내 지역의 나눔·교환 글을 보여준다.
- **화면 구성**
  - 지역 필터(기본값: 내 활동 지역, 변경 가능), 거래 상태 필터(전체 / 나눔중 / 예약중 / 완료), 거래 방식(나눔 / 교환)
  - 리스트: 썸네일, 제목, 지역, 거래 상태, 작성 시각, 관심 수, 댓글 수
- **처리 규칙**: 최신순, 커서 기반 페이지네이션, 완료 글은 기본 목록에서 아래로
- **예외**: 활동 지역 미설정 → 전체 지역 글 표시와 "활동 지역을 설정해 보세요" 안내

### COM-06 나눔 글 작성·거래 상태 변경 `P1`

- **설명**: 남는 재료를 나눔·교환 글로 올리고 거래 상태를 관리한다.
- **입력**
  - 필수: 제목, 본문, 거래 방식(나눔 / 교환), 지역(기본값: 내 활동 지역)
  - 선택: 사진 0~5장, 연결할 내 재고 (재고 상세의 "나눔하기"로 들어오면 자동 연결, 제목 기본값 "{재료명} 나눔해요")
- **처리 규칙**
  - post(board = share) + share_detail(trade_status = open) 생성
  - 거래 상태 변경: open ↔ reserved → done (done 이전에는 되돌릴 수 있고, done 이후에는 바꿀 수 없음)
  - done으로 변경 시 연결된 재고가 있으면 inventory_event(shared) 생성, status = shared, 점수 반영(shared_done), 첫 나눔이면 first_share 뱃지 판정
  - 거래 상태가 바뀌면 이 글에 관심·댓글을 남긴 사용자에게 알림
  - 삭제: 소프트 삭제 (연결된 재고는 그대로 active)
- **예외**: 이미 다른 나눔 글에 연결된 재고 → 연결 불가 안내

### COM-07 댓글·대댓글 `P1`

- **설명**: 게시글에 댓글과 1단계 답글을 단다.
- **처리 규칙**
  - 댓글 1~500자, 답글은 최상위 댓글에만 가능
  - 수정·삭제는 작성자만, 삭제는 "삭제된 댓글입니다"로 표시 (답글 보존)
  - 내 글에 댓글, 내 댓글에 답글이 달리면 알림
- **예외**: 삭제된 게시글 → 댓글 작성 불가

### COM-08 좋아요·관심 `P1`

- **설명**: 피드 글에는 좋아요, 나눔 글에는 관심을 누른다.
- **처리 규칙**: 같은 버튼으로 추가·취소 (토글), 사용자 × 게시글당 1개, 처음 누를 때 작성자에게 알림 (중복 알림 방지)

### COM-09 팔로우·언팔로우 `P1`

- **설명**: 다른 사용자를 팔로우하고 팔로잉 피드에서 글을 모아 본다.
- **처리 규칙**
  - 자기 자신은 팔로우 불가, 비공개 사용자도 승인 없이 팔로우 가능 (승인은 확장)
  - 팔로우 시 대상에게 알림 (같은 사람의 반복 팔로우는 1회만)
  - 팔로워·팔로잉 목록 조회 제공

## 8. 알림 (NOTI)

### NOTI-01 알림 생성 `P1`

- **설명**: 서비스 이벤트가 발생하면 알림을 만든다.

| 알림 종류 | 생성 시점 | 이동 대상 |
| :--- | --- | --- |
| expiring_summary | 매일 오전 9시, 임박 재료가 있을 때 (BAT-01) | 냉장고 (임박순) |
| expiry_check | 기한 경과 재료 발생 시 (BAT-02) | 해당 재고 확인 화면 |
| comment | 내 글에 댓글 | 게시글 |
| reply | 내 댓글에 답글 | 게시글 |
| reaction | 내 글에 좋아요·관심 | 게시글 |
| follow | 새 팔로워 | 팔로워 프로필 |
| trade_status | 관심·댓글 남긴 나눔 글의 거래 상태 변경 | 게시글 |
| badge_earned | 뱃지 획득 | 뱃지 목록 |
| weekly_report | 월요일 주간 확정 후 (BAT-03) | 지난주 리포트 |

- **처리 규칙**
  - 자기 자신의 행동에는 알림을 만들지 않음
  - 커뮤니티 알림은 dedup_key로 같은 사람 × 같은 대상 × 같은 종류는 1회만 생성
  - 탈퇴한 사용자에게는 알림을 만들지 않음

### NOTI-02 알림 목록·읽음 처리 `P1`

- **설명**: 오른쪽 위 종 아이콘에 안 읽은 개수를 표시하고 알림 목록을 보여준다.
- **처리 규칙**
  - 프론트엔드가 페이지 이동 시와 30초마다 안 읽은 개수 API를 호출 (폴링)
  - 목록은 최근 30일, 최신순, 커서 기반 페이지네이션
  - 알림을 누르면 읽음 처리 후 이동 대상으로 이동, "모두 읽음" 제공
  - 이동 대상이 삭제된 경우 "삭제된 콘텐츠예요" 안내

## 9. 관리자·데이터 적재 (ADM)

### ADM-01 기준 데이터 관리 `P0`

- **설명**: 재료 그룹, 표준 재료, 상품명 매핑, 시·군·구를 Django Admin에서 관리한다.
- **처리 규칙**
  - 초기 데이터는 시드(마이그레이션 또는 관리 명령)로 적재: 시·군·구 목록, 재료 그룹·표준 재료 100~150개, 초기 상품명 매핑
  - 표준 재료의 소비기한 기준값은 LLM 초안 → 사람 검수 → 적재, expiry_basis로 출처 표시
  - Admin에서 표준 재료 검색·필터(분류, 기준값 출처), 상품명 매핑의 출처·확정 횟수 확인
  - 재료 그룹마다 재료 그림 키(icon)와 시작 화면 기본 칩 여부(is_featured)를 함께 관리

### ADM-02 공공 레시피 수집·적재 `P0`

- **설명**: COOKRCP01 API에서 레시피를 수집해 정제·저장하고 임베딩한다.
- **흐름 (관리 명령으로 실행)**
  1. 수집: 인증키로 전체 레시피 조회 (1회 최대 1,000건, 약 1,156건이므로 2회)
  2. 정제: 이미지 URL https 변환, 조리 순서 MANUAL01~20을 배열로 변환 (빈 단계 제외, 끝 잔여 문자 제거), 원본은 raw_payload에 보존
  3. 재료 분리: LLM으로 재료 문자열을 재료명·분량 텍스트·구분(주재료/양념 등)·양념 여부로 분리하고 재료 그룹 매칭 제안
  4. 임베딩: 메뉴명 + 요리 종류 + 재료명 목록을 임베딩하여 저장 (텍스트 해시가 바뀐 레시피만 재임베딩)
- **처리 규칙**
  - source_recipe_id 기준으로 이미 있는 레시피는 갱신, 없는 레시피는 추가
  - 재료 그룹 매칭 비율이 낮은 레시피(예: 주재료 절반 이상 미매칭)는 is_recommendable = FALSE
  - 실행 결과 요약 출력: 수집 수, 신규·갱신 수, 매칭 실패 재료 수, 임베딩 수
- **예외**: API 호출 실패 → 재시도 후 중단, 이미 적재한 데이터는 유지

### ADM-03 레시피 재료 매칭 검수 `P1`

- **설명**: LLM이 매칭한 레시피 재료를 관리자가 확인·수정한다.
- **처리 규칙**
  - Admin에서 매칭 실패(group_id 없음) 재료를 재료명 빈도순으로 모아 보기
  - 같은 재료명을 한 번에 재료 그룹에 연결하는 일괄 수정 (match_source = manual)
  - 수정 후 해당 레시피 재임베딩 대상 표시

### ADM-04 점수 규칙·뱃지 관리 `P1`

- **설명**: 점수 규칙의 값과 뱃지 조건을 Admin에서 조정한다.
- **처리 규칙**
  - 초기 규칙·뱃지는 시드 데이터로 적재
  - 변경해도 과거 score_event는 바뀌지 않음
  - vw_weekly_score_check로 캐시 점수와 이벤트 합계 불일치 여부 확인

## 10. 배치 (BAT)

### BAT-01 임박 재료 요약 알림 `P1`

- **실행**: 매일 오전 9시
- **처리 규칙**: 사용자별로 남은 일수 3일 이하 active 재고가 있으면 요약 알림 1건 생성 (예: "오늘 임박 재료 3개 · 우유, 두부, 대파")

### BAT-02 기한 경과 확인 요청·방치 감점 `P1`

- **실행**: 매일 오전 0시 10분
- **처리 규칙**
  - 예상 소비기한이 지난 active 재고 중 아직 확인 요청을 하지 않은 재고 → expiry_check 알림 생성
  - 기한 경과 후 응답이 없는 재고 → 하루 1회 neglected 감점 (재료 1건당 최대 3일, still_have 응답 후 3일 동안은 감점하지 않음)

### BAT-03 주간 점수 확정·뱃지 판정 `P1`

- **실행**: 매주 월요일 오전 0시 30분
- **처리 규칙**
  - 지난주 weekly_score 확정 (is_finalized = TRUE, final_score 기록)
  - 주간·연속 뱃지 판정 후 user_badge 생성, badge_earned 알림
  - 지난주 활동이 있는 사용자에게 weekly_report 알림
  - 이번 주 weekly_score는 첫 점수 이벤트 발생 시 생성 (활동 없는 사용자의 빈 행은 만들지 않음)
