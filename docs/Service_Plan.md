# 서비스 기획서

```
본 프로젝트는 온라인에서 구매한 식재료를 결제내역 캡처만으로 자동 등록하고,
재료별 예상 소비기한을 관리하여 임박한 재료를 활용할 수 있는 레시피를 추천하는
냉장고 재료 관리·공유 웹 서비스를 구축하는 것을 목표로 합니다.

사용자는 쿠팡, 마켓컬리 등 플랫폼에서 재료를 구매한 뒤
주문(결제) 내역 캡처를 업로드하는 것만으로 재고를 등록할 수 있으며,
서비스는 비전 LLM을 통해 품목·수량·가격·구매일을 구조화하고
재료별 기준값과 보관 상태를 바탕으로 예상 소비기한을 산정합니다.
처음 방문한 사용자는 가입 없이 가진 재료를 골라 만들 수 있는 레시피를 먼저 확인할 수 있습니다.

레시피 추천은 공공 레시피 DB를 근거로 한 RAG(검색 증강 생성) 방식으로,
임박 재료와 사용자의 요리 이력, 식사 시간대를 바탕으로 실제 레시피 중에서 추천하고 그 이유를 설명합니다.
서비스에 접속하면 "오늘의 냉장고" 카드로 재고 상태와 지금 시간대에 맞는 레시피를 바로 보여줍니다.

또한 결제내역에서 얻은 구매 가격으로 식비·폐기 금액을 가계부처럼 보여주고,
요리하거나 재료를 버릴 때마다 바로 바뀌는 주간 냉장고 관리 점수와
요리 피드·레시피 공유·남는 재료 나눔 게시판을 통해
혼자서는 이어가기 어려운 식재료 관리를 다른 사용자와 함께 지속할 수 있도록 합니다.

본 프로젝트는 단순한 재고 기록 앱에 그치지 않고,
이미지 인식 → 재료 정규화 → 소비기한 산정 → RAG 레시피 추천 → 재고 차감 → 점수·공유로 이어지는
데이터 흐름을 설계하여, 사용 이력이 쌓일수록 추천과 분석이 개인화되는 구조를 구축하는 데 중점을 둡니다.
```

- **서비스명**: (가칭) 냉장고 레시피 추천 서비스
- **서비스 형태**: 웹 서비스 (데스크톱 우선, 모바일 화면 대응은 확장)
- **개발 형태**: 2인 팀 프로젝트
- **주요 사용자**: 1인 가구, 자취생 등 식재료 관리가 어려운 사용자
- **사용 데이터**: 사용자 결제내역 캡처 이미지, 재료별 소비기한 기준 테이블(직접 구축), 공공 레시피 데이터 (식품안전나라 조리식품 레시피 DB, COOKRCP01 API)

---

## 1. 문제 정의

```
1인 가구는 소량·다품목으로 식재료를 구매하는 경우가 많고,
온라인 장보기 비중이 높아 구매처와 구매 시점이 분산되어 있다.

이로 인해 냉장고에 어떤 재료가 있는지, 언제까지 먹어야 하는지를 기억하기 어렵고,
결국 재료를 사용하지 못한 채 소비기한이 지나 폐기하는 일이 반복된다.
또한 남은 재료로 무엇을 만들 수 있는지 매번 따로 검색해야 하여
"오늘 뭐 해먹지"라는 고민이 반복되고, 재료가 있음에도 배달이나 외식을 선택하게 된다.

특히 최소 판매 단위가 1인 기준보다 큰 재료는 혼자서 기한 내에 다 쓰기 어렵지만,
남는 재료를 주변과 나눌 방법이 마땅치 않고,
버린 재료가 얼마짜리였는지, 식재료에 얼마를 쓰는지는 확인할 방법이 없어
낭비가 반복되어도 체감하기 어렵다.

기존 냉장고 관리 앱은 재료를 하나씩 직접 입력해야 하는 경우가 많고,
혼자 기록하는 구조인 데다 오늘 한 요리가 낭비를 얼마나 줄였는지 바로 확인할 수 없어
동기가 쉽게 떨어지고 지속적으로 사용하기 어렵다.

따라서 입력 부담을 최소화하면서, 보유 재료의 소비기한과 활용 방법을 한 번에 확인하고,
행동의 결과를 즉시 확인하며 다른 사용자와 요리·재료를 공유할 수 있는 서비스가 필요하다.
```

- **재고 파악의 어려움**
  - 구매처와 구매 시점이 분산되어 보유 재료와 소비기한을 기억하기 어려움
- **식재료 폐기와 불필요한 비용 발생**
  - 사용하지 못한 재료의 폐기, 재료가 있음에도 배달·외식 선택
- **반복적인 메뉴 고민**
  - 남은 재료로 만들 수 있는 요리를 매번 따로 검색해야 함
- **혼자 쓰기 어려운 재료**
  - 1인 기준보다 큰 판매 단위의 재료를 기한 내에 다 쓰기 어렵고, 나눌 곳이 없음
- **보이지 않는 식비와 낭비**
  - 식재료 지출과 버린 재료의 금액을 확인할 방법이 없어 낭비를 체감하기 어려움
- **높은 입력 부담과 낮은 지속 동기**
  - 재료를 수동으로 하나씩 입력해야 하고, 행동의 결과가 바로 보이지 않아 지속 사용이 어려움

## 2. 서비스 목적

```
본 프로젝트의 주요 목적은 식재료 등록부터 소비까지의 과정을 최소한의 입력으로 관리하고,
소비기한이 임박한 재료를 우선 활용하며, 그 결과를 바로 확인하고 다른 사용자와 공유하며
이어갈 수 있는 서비스를 구축하는 것입니다.

이를 위해 다음과 같은 목표를 설정합니다.

- 결제내역 캡처 이미지만으로 품목, 수량, 가격, 구매일을 자동으로 추출하여
  재료 등록의 입력 부담을 최소화

- 다양한 상품명을 표준 재료로 정규화하고,
  재료별 기준값과 보관 상태를 바탕으로 예상 소비기한을 일관된 기준으로 산정

- 공공 레시피 DB를 근거로 한 RAG 방식으로,
  임박 재료·요리 이력·식사 시간대를 반영한 레시피를 실제 레시피 중에서 추천하고,
  접속 시 "오늘의 냉장고" 카드로 바로 제안

- 가입 전에도 가진 재료로 만들 수 있는 레시피를 바로 보여주어
  서비스의 가치를 먼저 체험하고 자연스럽게 가입으로 이어지도록 함

- 레시피 완료 체크와 사용자 확인을 통해
  실제 냉장고 상태와 서비스의 재고가 일치하도록 유지

- 구매·소비·폐기 이력을 금액 단위로 집계하여 오늘·이번 주의 식비와 폐기 금액을 보여주고,
  요리·폐기·나눔이 일어날 때마다 즉시 바뀌는 주간 냉장고 관리 점수와 뱃지를 제공

- 요리 피드, 레시피 공유, 팔로우, 남는 재료 나눔 게시판을 통해
  식재료 관리를 혼자가 아닌 커뮤니티 안에서 지속하도록 지원
```

- **서비스 목적**
  - 식재료 등록부터 소비까지를 최소한의 입력으로 관리
  - 소비기한 임박 재료를 우선 활용하도록 지원
  - 즉각적인 점수 변화와 공유를 통해 관리를 지속할 동기 제공
- **서비스 목표**
  - 캡처 이미지 기반 재료·가격 자동 등록
  - 재료 정규화 및 예상 소비기한 자동 산정
  - RAG 기반 임박 재료·시간대 맞춤 레시피 추천, 접속 시 "오늘의 냉장고" 카드
  - 가입 없이 재료를 골라 레시피를 먼저 보는 체험형 시작 화면
  - 완료 체크와 사용자 확인을 통한 재고 정합성 유지
  - 일·주 단위 식비·폐기 분석과 실시간으로 변동하는 주간 냉장고 관리 점수
  - 요리 피드·레시피 공유·팔로우·나눔 게시판

## 3. 기대 효과

```
본 프로젝트를 통해 식재료 관리의 입력 부담을 줄이고
보유 재료를 활용하고 공유하는 흐름을 하나의 서비스로 연결함으로써,
다음과 같은 효과를 기대할 수 있습니다.

- 캡처 업로드만으로 재료가 등록되어,
  재고 관리를 지속적으로 이어가기 위한 진입 장벽이 낮아짐

- 가입 전에 가진 재료로 만들 수 있는 레시피를 먼저 확인할 수 있어
  처음 방문한 사용자도 서비스의 쓸모를 바로 체감함

- 임박 재료 중심의 레시피 추천을 통해
  재료를 기한 내에 사용하게 되어 식재료 폐기와 식비가 줄어듦

- 접속하자마자 지금 시간대에 맞는 레시피와 추천 이유를 확인할 수 있어
  메뉴 선택에 드는 시간과 고민이 줄어듦

- 혼자 다 쓰기 어려운 재료를 나눔 게시판으로 주변과 나누어
  폐기 자체를 줄일 수 있음

- 요리 완료·폐기 직후 점수와 게이지가 바로 바뀌어
  오늘의 행동이 낭비에 어떤 영향을 미쳤는지 즉시 체감하고, 다음 행동을 바꿀 동기가 생김

- 요리 피드와 팔로우를 통해 다른 사용자의 요리를 참고하고,
  자신의 기록을 공유하며 서비스를 지속적으로 사용하게 됨

- 레시피 추천·완료 이력과 재료 소진·폐기 이력이 축적되어,
  추천 개인화와 소비 패턴 분석으로 확장 가능한 데이터 기반이 마련됨
```

- **기대 효과**
  - 캡처 업로드만으로 재료 등록 → 지속 사용을 위한 진입 장벽 감소
  - 가입 전 체험으로 첫 방문 사용자의 가입 전환
  - 임박 재료 레시피 추천을 통한 식재료 폐기 및 식비 절감
  - 접속 즉시 시간대 맞춤 추천으로 메뉴 선택 시간과 고민 감소
  - 나눔 게시판을 통한 남는 재료 폐기 감소
  - 행동 직후의 점수 변화로 낭비 감소 효과를 즉시 체감
  - 피드·팔로우를 통한 지속 사용 동기 부여
  - 사용 이력 축적을 통한 개인화 추천 및 소비 패턴 분석 기반 마련

## 4. 서비스 범위 및 전제

```
본 프로젝트는 1인 사용자의 식재료 등록, 소비기한 관리, 레시피 추천, 재고 정리까지의 핵심 흐름과
이를 지속하게 하는 점수·커뮤니티 기능을 하나의 웹 서비스로 구현하는 데 초점을 둡니다.
2인 팀이 정해진 기간 안에 완성할 수 있도록 핵심 기능을 MVP로 두고,
나머지는 확장 기능으로 분류합니다.

서비스 범위 (MVP)

- 비회원 체험 (시작 화면)
  가입 없이 가진 재료를 골라 만들 수 있는 레시피 목록과 레시피 상세를 확인
  재료 저장·캡처 등록·요리 완료를 시도하면 가입 안내, 가입 직후 고른 재료를 확인해서 냉장고에 넣기
  비회원 레시피 결과는 LLM 없이 재료 키워드 매칭으로만 제공

- 회원·프로필 관리
  이메일 회원가입·로그인, 정보 수정, 탈퇴(비활성화 방식)
  프로필(닉네임, 프로필 이미지, 한 줄 소개, 가구 인원, 선호 요리 종류, 활동 지역(시·군·구 선택), 공개 여부)
  프로필에 이번 주 냉장고 관리 점수와 뱃지 표시

- 재고 관리
  결제내역 캡처 업로드 → 비전 LLM 인식(품목·수량·가격·구매일) → 확인 화면 → 재고 저장
  재료 직접 추가(여러 건 한 번에)·조회·수정(보관 위치 변경·소분, 개봉, 남은 양)·소진/폐기 처리
  냉장고 그림(냉동칸·냉장 선반·채소칸·도어·실온 선반) 안에 재료를 배치하고, 끌어서 보관 위치 변경
  재료별 기준값과 보관 상태(냉장/냉동/실온, 개봉 여부)를 반영한 예상 소비기한 산정
  소비기한 임박 알림(하루 1회 요약) 및 기한 경과 시 사용자 확인("아직 있나요?")

- RAG 레시피 추천
  임박 재료·보유 재료로 레시피 DB에서 후보 검색 → LLM이 후보 중에서 추천 레시피 선택 및 이유 설명
  사용자의 최근 완료 레시피, 선호 요리 종류, 식사 시간대를 함께 반영
  레시피 완료 체크 시 보유 재료별로 사용량("다 씀 / 절반 / 조금 / 안 씀")을 선택하여 재고 차감

- 오늘의 냉장고 카드
  접속 시 시간대(아침·점심·간식·저녁)별로 하루 한 번씩 카드 표시
  오늘의 재고 상태(임박 재료, 기한 경과 확인 필요 재료, 이번 주 점수)와 지금 시간대에 맞는 추천 레시피 1개
  "다른 추천 보기", "오늘은 그만 보기" 제공

- 식비·폐기 분석
  오늘의 변화: 오늘 소진한 재료 금액, 버린 재료 금액, 점수 변화
  주간 리포트: 이번 주 식재료 구매 금액, 소진·폐기·나눔 금액, 자주 버리는 재료, 지난주 대비 변화
  월간 합계: 가계부 형태로 월별 구매 금액(할인, 배송비 별도)과 폐기 금액을 보조 탭으로 제공

- 주간 냉장고 관리 점수
  점수는 주 단위로 운영하며 매주 월요일에 기본 점수로 리셋
  레시피 완료, 다 씀, 폐기, 기한 경과 방치, 나눔 완료 등 재고 이벤트가 발생할 때마다 즉시 가감
  이벤트 직후 "+N점 / -N점"과 그 이유(예: 임박 재료 2개 소진)를 표시하고 게이지를 갱신
  홈 화면에 이번 주 점수 게이지와 요일별 점수 추이 그래프 제공
  주간 달성 조건(예: 이번 주 폐기 0원, 임박 재료 모두 소진), 연속 달성, 첫 달성에 따른 뱃지 부여

- 커뮤니티
  요리 피드(인스타그램형): 내가 만든 요리 자랑과 레시피 공유를 하나의 피드로 제공하고 탭으로 구분,
  사진·좋아요·댓글(1단계 대댓글), 요리 완료 기록을 연결하면 "임박 재료 N개 · N원어치 소진" 표시
  레시피 공유: 재료(재료명 + 분량)와 조리 순서를 단계별로 입력하는 구조화된 레시피 작성,
  다른 사용자도 공공 레시피와 똑같이 완료 체크 가능
  팔로우·팔로잉: 팔로우한 사용자의 피드만 모아 보기
  나눔·교환 게시판(당근마켓형): 제목·지역·거래 상태 중심 목록, 재고에서 바로 나눔 글 등록,
  관심·댓글, 거래 상태(나눔중 / 예약중 / 완료), 완료 시 재고 정리와 점수 반영

- 알림
  임박 재료 요약, 기한 경과 확인, 댓글·답글·좋아요·관심·팔로우, 거래 상태 변경, 뱃지 획득, 주간 리포트
  화면의 종 아이콘에 안 읽은 개수 표시

서비스 전제 및 제외 사항

- 쇼핑 플랫폼은 소비자용 구매내역 API를 제공하지 않으므로,
  플랫폼 연동 대신 결제내역 캡처 이미지를 입력으로 사용합니다.

- 캡처 인식용 학습 데이터가 없으므로 자체 OCR 모델을 학습하지 않고 비전 LLM API를 사용합니다.
  정확도 평가는 팀원이 직접 수집한 결제내역 캡처 20~30장의 정답 데이터로 수행합니다.

- 결제내역에는 소비기한 정보가 포함되지 않으므로,
  소비기한은 실제 표기 날짜가 아닌 "예상 소비기한"으로 제공합니다.

- 식약처 소비기한 참고값은 오픈 API로 제공되지 않고 가공식품 위주이므로,
  자주 구매하는 재료 100~150개의 기준 테이블을 직접 구축합니다.
  가공식품은 식약처 참고값 안내서를, 신선식품은 일반 보관 기준을 참고하며, LLM 초안을 사람이 검수합니다.

- 공공 레시피(약 1,150건)는 재료 정보가 형식이 제각각인 하나의 문자열로 제공되므로,
  적재 시 LLM으로 재료를 분리하고 재료 그룹에 매칭한 뒤 검수합니다.
  분량은 숫자로 변환하지 않고 원문 텍스트로 보존하며, 차감량은 사용자가 완료 시 선택합니다.

- 가격은 품목별 실 결제 금액을 기준으로 하며, 주문 단위 할인과 배송비는 품목에 배분하지 않고
  식비 분석에서 별도 항목으로 집계합니다. 폐기 금액은 구매 가격 × 남은 비율로 산정한 추정값입니다.

- 점수는 1인 가구가 매일 요리하지 않는 점을 고려하여 일 단위가 아닌 주 단위로 운영하고,
  일 단위는 "오늘의 변화"로만 보여줍니다.
  "최근 7일" 이동 구간 방식은 행동이 없어도 점수가 바뀌어 혼란을 주므로 주간 리셋 방식을 사용합니다.
  이벤트별 가감 점수와 기본 점수는 구현 후 테스트 사용을 통해 조정합니다.

- LLM은 검색된 레시피 후보 중에서만 추천하도록 제한하고,
  응답의 레시피 ID가 후보에 포함되는지 서버에서 검증하여 존재하지 않는 레시피 생성을 막습니다.
  LLM 호출이 실패하면 검색 상위 후보로 대체 추천합니다.

- 공공 레시피의 요리 종류 분류는 거칠기 때문에(예: 크로켓이 후식으로 분류),
  식사 시간대는 강한 필터가 아닌 검색·프롬프트의 참고 정보로 사용합니다.

- 사용자 공유 레시피는 품질이 제각각이므로 MVP에서는 RAG 추천 후보에서 제외합니다.

- 비회원 기능은 비용이 들지 않도록 LLM을 호출하지 않고, 기록도 남기지 않습니다.

- 알림은 실시간 연결(웹소켓) 대신 주기적 조회(폴링) 방식으로 전달합니다.
  내 행동에 대한 피드백(점수 변화 등)은 API 응답으로 즉시 보여줍니다.

- 나눔·교환 게시판은 게시글과 댓글 수준으로 제공하며,
  1:1 채팅, 위치 인증, 거래 안전 기능은 범위에서 제외합니다.

- 소셜 로그인, 레시피 포크, 소진 플래너, 부족 재료 안내, 개인화 랭킹 모델, 보관·손질 Q&A 게시판,
  동네 랭킹, 영상 레시피 요약, AI 챗봇, 레시피 퀴즈, 알림 설정 등은 확장 기능으로 분류합니다.

- 화면은 데스크톱 우선으로 설계·구현하며, 모바일 화면 대응, 모바일 웹앱(PWA), 네이티브 앱은 확장 범위로 둡니다.
```

- **서비스 범위 (MVP)**
  - 비회원 체험: 가입 없이 재료 선택 → 레시피 확인, 가입 직후 고른 재료를 냉장고로
  - 회원·프로필 관리: 이메일 로그인 + 닉네임, 시·군·구 활동 지역, 점수·뱃지 표시
  - 재고 관리: 캡처 인식 → 확인 → 저장, 재고 CRUD, 냉장고 그림·드래그, 예상 소비기한, 임박 알림·기한 경과 확인
  - RAG 레시피 추천: 후보 검색 → LLM 선택·설명 → 완료 체크(사용량 선택) → 재고 차감
  - 오늘의 냉장고 카드: 접속 시 시간대별 1회, 재고 상태 + 시간대 맞춤 레시피
  - 식비·폐기 분석: 오늘의 변화, 주간 리포트, 월간 합계(보조)
  - 주간 냉장고 관리 점수: 이벤트마다 즉시 가감, 게이지·요일별 추이, 뱃지
  - 커뮤니티: 요리 피드(자랑·레시피 공유), 팔로우, 나눔·교환 게시판
  - 알림: 재고·커뮤니티·점수 알림, 폴링 방식
- **전제 및 제외 사항**
  - 플랫폼 API 연동 대신 결제내역 캡처 이미지를 입력으로 사용
  - 학습 데이터가 없어 비전 LLM 사용, 자체 캡처 20~30장으로 정확도 평가
  - 소비기한은 "예상 소비기한", 기준 테이블은 직접 구축 (식약처 참고값 + 일반 보관 기준)
  - 공공 레시피 재료는 적재 시 LLM으로 정리·매칭, 분량은 텍스트 보존, 차감량은 사용자 선택
  - 품목별 실 결제 금액 기준 (주문 할인·배송비는 별도 집계), 폐기 금액은 추정값
  - 점수는 주간 리셋 + 이벤트 단위 즉시 변동, 일 단위는 "오늘의 변화"로 표시 (가감값은 테스트 후 조정)
  - LLM은 검색된 후보 레시피 중에서만 추천 (서버 검증, 실패 시 대체 추천)
  - 식사 시간대는 참고 정보로만 사용, 사용자 레시피는 MVP에서 추천 후보 제외
  - 비회원 기능은 LLM 호출·기록 없음
  - 알림은 폴링, 나눔 게시판은 게시글·댓글 수준 (채팅·위치 인증 제외)
  - 데스크톱 우선 웹으로 구현 (모바일 화면·PWA·네이티브 앱은 확장)

## 5. 사용자 Flow

```
본 서비스는 사용자가 재료를 구매하는 시점부터 요리 후 재고가 정리되고
그 결과를 점수로 확인하고 공유하는 시점까지를 하나의 흐름으로 연결하는 것을 목표로 합니다.

(첫 방문) 시작 화면에서 재료 선택 → 레시피 확인 → 가입 → 고른 재료 냉장고에 넣기

구매 → 캡처 업로드 → 인식 및 확인 → 재고 등록 → (접속 시) 오늘의 냉장고 카드 → 레시피 추천 → 완료 체크 → 재고 정리 → 점수 변화 확인 → 피드 공유

커뮤니티와 분석 기능은 위 흐름에서 쌓인 데이터를 바탕으로 제공됩니다.

(수시) 이벤트마다 점수 게이지 변화 확인 / 나눔 글 작성 / 팔로우 피드 확인 / 알림 확인
(매일) 시간대별 오늘의 냉장고 카드, 임박 재료 요약 알림, 오늘의 변화 확인
(매주) 주간 리포트·뱃지 확인, 점수 리셋   (매월) 가계부 월간 합계 확인
```

- **첫 방문 체험**
  - 시작 화면에서 가진 재료를 칩으로 골라 만들 수 있는 레시피 목록과 상세를 확인 (가입 불필요)
  - 재료 저장·캡처 등록·요리 완료를 시도하면 가입 안내
  - 가입 직후 "고른 재료를 냉장고에 넣을까요?" 안내 → 재료 종류·수량을 확인하고 저장
- **구매 및 캡처 업로드**
  - 사용자가 쿠팡, 마켓컬리 등에서 재료를 구매한 뒤 주문(결제) 내역을 캡처
  - 서비스의 "캡처 불러오기"로 이미지 업로드
- **인식 및 확인**
  - 캡처 이미지에서 품목, 수량, 가격, 구매일을 추출하고 표준 재료로 정규화
  - 인식 결과를 확인 화면에서 사용자가 수정한 뒤 저장 (품목, 수량, 가격, 보관 위치)
  - 캡처 없이 재료를 직접 추가하는 것도 가능 (여러 건 한 번에)
- **재고 등록 및 소비기한 산정**
  - 재료별 기본 보관 위치와 기준값으로 예상 소비기한 자동 부여
  - 냉장고 그림에서 재료를 끌어 냉동칸 등으로 옮기거나 상세에서 보관 위치를 바꾸면 소비기한 재계산 (일부만 옮기는 소분 가능)
  - 개봉 처리 시 소비기한 재계산
- **오늘의 냉장고 카드**
  - 접속하면 지금 시간대(아침 05~10시, 점심 10~14시, 간식 14~17시·22~05시, 저녁 17~22시)에 맞춰 카드 표시
  - 재고 상태(임박 재료, 기한 경과 확인 필요 재료, 이번 주 점수)를 먼저 보여주고, 추천 레시피는 불러오는 대로 채움
  - 같은 날 같은 시간대에는 한 번만 표시, "오늘은 그만 보기"를 누르면 그날은 다시 표시하지 않음
- **임박 알림 및 레시피 추천**
  - 소비기한 임박 재료를 하루 1회 요약 알림으로 안내 (오전 9시)
  - 임박 재료를 활용할 수 있는 레시피를 추천 이유와 함께 제공
- **완료 체크 및 재고 정리**
  - 레시피 완료 체크 시 보유 재료 목록(같은 재료는 소비기한이 빠른 것 우선)에서 재료별 사용량을 선택하여 재고 차감
    - 양으로 관리하는 재료: 다 씀 / 절반 / 조금 / 안 씀
    - 개수로 관리하는 재료: 사용한 개수 입력
    - 양념 등 있음/없음으로 관리하는 재료: 차감 없음
  - 레시피 외 소비는 재료 목록에서 직접 다 씀/버림 처리, 잘못 처리한 경우 취소 가능
  - 기한 경과 재료는 "아직 있나요?" 확인을 통해 상태 갱신
- **점수 변화 확인**
  - 완료 체크·다 씀·버림·나눔 완료 직후 "+N점 / -N점"과 이유를 표시하고 게이지 갱신
  - 홈 화면에서 이번 주 점수 게이지와 요일별 추이, 오늘의 변화(아낀 금액·버린 금액) 확인
- **피드 공유 및 팔로우**
  - 완료한 요리를 사진과 함께 피드에 자랑 글로 올리기 (완료 기록 연결 시 소진 재료·금액 자동 표시)
  - 직접 만든 레시피를 재료와 조리 순서로 작성하여 공유
  - 다른 사용자를 팔로우하고 팔로우 피드에서 요리를 확인, 좋아요·댓글
- **나눔·교환**
  - 혼자 다 쓰기 어려운 재료를 재고 목록에서 바로 나눔 글로 등록 (지역은 활동 지역이 기본값)
  - 내 지역의 나눔 글을 목록으로 보고 관심·댓글로 약속
  - 거래 상태를 나눔중 → 예약중 → 완료로 변경 (완료 시 재고 정리와 점수 반영)
- **알림 확인**
  - 종 아이콘의 안 읽은 개수를 확인하고, 알림을 누르면 해당 게시글·재고·리포트로 이동
- **주간 리포트 및 뱃지**
  - 매주 월요일 지난주 리포트(구매·소진·폐기·나눔 금액, 자주 버린 재료, 전주 대비)와 최종 점수 확인
  - 달성 조건을 채운 경우 뱃지 획득, 새 주 점수는 기본 점수에서 다시 시작
- **월간 가계부**
  - 필요할 때 월별 식비(구매 금액, 할인, 배송비)와 폐기 금액 합계 확인

## 6. 시스템 Flow

```
본 프로젝트는 이미지 입력부터 추천·공유까지의 처리 과정을 단계별로 분리하여 설계함으로써,
각 단계의 정확도를 독립적으로 측정하고 개선할 수 있는 구조를 확보하는 것을 목표로 합니다.

전체 시스템 Flow는 다음과 같은 구조로 구성됩니다.

Image Input → Recognition → Normalization → Inventory → Recommendation(RAG) → Feedback
                                                │                                     │
                                                └──────── Score · Report ─────────────┘
                                                                  │
                                                       Community · Notification
```

- **Image Input**
  - 업로드를 통해 결제내역 캡처 이미지를 서버로 전송
  - 원본 이미지는 저장소에 보존하여 재처리 및 인식 검증에 활용
- **Recognition**
  - 비전 LLM을 활용하여 이미지에서 품목, 수량, 가격, 구매일을 추출 (업로드 요청 안에서 동기 처리, 시간 제한 20초)
  - 플랫폼별로 다른 레이아웃에 대응하기 위해 규칙 기반 파싱 대신 구조화 출력(JSON) 방식 사용
- **Normalization**
  - "곰곰 무항생제 대란 30구"와 같은 다양한 상품명을 표준 재료(계란)로 매핑
  - 수량 및 단위 표기(6입, 2L x 6, 1kg 등) 정리
  - 재료 기준 테이블과 연결하여 예상 소비기한 산정
- **Inventory**
  - 사용자별 재고, 수량, 구매 가격, 보관 상태, 예상 소비기한, 상태(보유/소진/폐기/나눔)를 관리하는 핵심 계층
  - 일부만 보관 위치를 바꾸면 구매 건을 둘로 나누어(소분) 가격을 비율대로 배분
  - 이후 추천, 알림, 분석, 점수, 나눔 글의 단일 데이터 소스로 활용
- **Recommendation (RAG)**
  - Indexing: COOKRCP01 API로 레시피(약 1,150건)를 수집해 정제·저장하고, 재료 문자열은 LLM으로 분리·재료 그룹 매칭 후 검수, 메뉴명·요리 종류·재료명을 임베딩하여 pgvector에 저장
  - Retrieval: 임박 재료·보유 재료로 후보 레시피 20~30개 검색 (임베딩 유사도 + 재료명 키워드 포함 여부, 시간대는 요리 종류 가중치로 반영)
  - Generation: 후보, 임박 재료(남은 일수), 최근 완료 레시피, 선호 요리 종류, 식사 시간대를 LLM에 전달하여 추천 레시피 선택
  - Output: 레시피 ID, 추천 이유, 사용되는 임박 재료, 대체 재료 제안을 JSON으로 반환하고 서버에서 후보 포함 여부 검증, 실패 시 검색 상위 후보로 대체
  - 같은 날 같은 재고 조합에 대한 추천 결과는 캐싱하여 LLM 호출 비용과 응답 시간 절감
  - 요청마다 입력 스냅샷, 검색 후보, LLM 응답, 응답 시간, 토큰 사용량을 기록하여 검색 품질·추천 성과·비용을 측정
  - 오늘의 냉장고 카드도 같은 추천 흐름을 사용하며, 요청 경로와 시간대를 함께 기록
  - 비회원 레시피 보기는 LLM·임베딩 없이 재료 그룹 키워드 매칭만 사용
- **Feedback**
  - 레시피 완료 체크(재료별 사용량), 직접 소진/폐기, 남은 양 수정, 기한 경과 확인 응답, 나눔 완료, 처리 취소를 금액과 함께 이벤트로 저장
  - 재고 정합성 유지, 추천 개인화, 점수 산정, 소비기한 기준값 보정에 활용
- **Score · Report**
  - Score: 재고 이벤트가 저장될 때 점수 규칙을 적용하여 가감 점수와 사유를 함께 기록하고, 이번 주 점수를 즉시 갱신
    - 가점: 임박 재료 소진(남은 일수가 적을수록 가중), 재료 다 씀, 나눔 완료 (하루 가점 상한 적용)
    - 감점: 폐기(폐기 금액 비례), 기한 경과 후 미확인 방치(일 단위, 재료 1건당 최대 3일)
    - 취소: 잘못된 처리를 취소하면 반대 점수의 이벤트를 기록
    - 주간 리셋: 매주 월요일 배치에서 지난주 점수를 확정·저장하고, 뱃지 조건을 판정한 뒤 새 주 점수 생성
  - Report: 재고와 이벤트 데이터를 일·주 단위로 집계하여 오늘의 변화, 주간 구매·소진·폐기·나눔 금액, 자주 버리는 재료, 전주 대비 산출
    - 월간 가계부는 같은 데이터를 월 단위로 집계하여 보조 제공
  - 계산식을 분석용 View로 고정하여 화면·API·분석에서 동일한 기준 사용
- **Community**
  - 공통 게시글 구조에 피드(자랑·레시피 공유)와 나눔·교환 게시판의 전용 정보를 분리하여 관리
  - 좋아요·관심, 댓글(1단계 대댓글), 이미지(최대 5장), 팔로우 관계 관리
  - 레시피 완료 기록, 사용자 레시피, 재고 항목을 게시글에 연결하여 서비스 데이터와 커뮤니티를 하나로 연결
- **Notification**
  - 재고(임박 요약·기한 경과 확인), 커뮤니티(댓글·답글·반응·팔로우·거래 상태), 점수(뱃지·주간 리포트) 알림 생성
  - 같은 사람 × 같은 대상 × 같은 종류의 커뮤니티 알림은 한 번만 생성
  - 프론트엔드가 페이지 이동 시와 30초마다 안 읽은 개수를 조회 (폴링)

## 7. 기술 스택 및 구현

```
본 프로젝트는 데스크톱 우선 웹으로 구현하며,
이미지 인식, RAG 추천, 점수·분석 로직은 Python 기반 백엔드에서 처리합니다.

프론트엔드와 백엔드를 분리하여 설계함으로써,
향후 모바일 화면이나 모바일 앱으로 확장하더라도 백엔드와 데이터 구조를 그대로 재사용할 수 있는 구조를 지향합니다.
```

- **Frontend**
  - Vue 3 (SPA, 데스크톱 우선 레이아웃)
  - 냉장고 그림 화면 (재료 그림 배치, 끌어서 보관 위치 변경)
  - 점수 게이지·요일별 추이·리포트 시각화: Chart.js 등 차트 라이브러리
  - 이벤트 직후 점수 변화 표시 (토스트·게이지 애니메이션)
  - 오늘의 냉장고 카드 (재고 요약 먼저 표시, 추천은 로딩 후 채움)
  - 알림: 페이지 이동 시 + 30초 주기 폴링으로 안 읽은 개수 조회
  - 배포: Netlify 또는 Vercel
- **Backend**
  - Django + Django REST Framework (Python)
  - 회원: 커스텀 User 모델(이메일 로그인 + 닉네임), 첫 마이그레이션 전에 설정
  - 주요 API: 회원·프로필 / 비회원 레시피 보기 / 캡처 업로드·인식 / 재고 CRUD·보관 위치 변경·소분 / RAG 레시피 추천·오늘의 냉장고 / 완료 체크·재고 차감·취소
  - API: 오늘의 변화·주간 리포트·월간 합계 / 주간 점수·점수 이력·뱃지 / 피드·레시피 작성·댓글·반응 / 팔로우 / 나눔·교환 게시판 / 알림
  - 재고 이벤트 저장 시 점수 규칙을 함께 적용하여 응답에 점수 변화량 포함
  - 인증: DRF 기본 토큰 인증 (MVP는 만료 없음, 확장 시 JWT 또는 소셜 로그인용 라이브러리로 전환)
  - 데이터 관리: Django Admin (재료 기준 테이블, 재료 매핑, 레시피·레시피 재료 검수, 점수 규칙·뱃지 조건 조회·수정)
  - 시드 데이터: 시·군·구 목록, 재료 기준 테이블, 점수 규칙, 초기 뱃지
  - 스케줄러: 매일 오전 임박 요약 알림·기한 경과 확인·방치 감점, 매주 월요일 점수 확정·리셋·뱃지 판정·주간 리포트 알림
  - 배포: Render 또는 Railway
- **Database**
  - PostgreSQL + pgvector (Supabase 또는 Render/Railway 호스팅, 배포 전 pgvector 지원 확인)
  - 이미지 저장소: 개발은 Django media 폴더, 배포는 Supabase Storage 등 외부 스토리지
  - 주요 테이블: 회원·지역, 재료 기준, 레시피(임베딩 포함)·레시피 재료, 캡처·인식 결과, 재고·재고 이벤트,
    추천 요청·노출·완료, 게시글(공통·피드·나눔)·이미지·댓글·반응, 팔로우, 점수 규칙·점수 이벤트·주간 점수·뱃지, 알림
  - 리포트 View: 오늘의 변화, 주간 리포트, 월간 가계부, 재료별 활용률, 주간 점수 검증
- **AI / Model**
  - 비전 LLM API: 캡처 이미지 인식 + 구조화 + 정규화 (2~3개 모델 비교 후 선정)
  - 텍스트 LLM API: RAG 레시피 선택·추천 이유 생성, 공공 레시피 재료 분리·매칭, 재료 기준값 초안 (구조화 출력)
  - 임베딩 API: 레시피 임베딩 및 후보 검색
  - 재료 정규화: 규칙(사전) 기반 → 임베딩 유사도 기반으로 고도화
- **Data**
  - 공공 레시피 데이터: 식품안전나라 조리식품 레시피 DB (COOKRCP01 API, 인증키 발급 필요, 약 1,150건)
  - 재료별 소비기한 기준 테이블: 식약처 소비기한 참고값 안내서(가공식품) + 일반 보관 기준(신선식품)으로 직접 구축
  - 시·군·구 목록: 공공데이터포털 행정구역 코드 (시드 데이터)
  - 인식 평가용 결제내역 캡처 20~30장과 정답 데이터 (팀원 직접 수집)

## 8. 확장 계획

```
MVP를 완성한 이후,
추천·계획의 개인화 수준을 높이고 커뮤니티와 AI 기능을 넓히는 방향으로 기능을 확장합니다.
```

- **추천·계획 고도화**
  - 소진 플래너: 임박 재료를 기한 내 최대한 소진하는 주간 레시피 조합 제안 (탐욕 알고리즘 → 정수계획법)
  - 부족 재료 안내: 주간·월간 기준으로 다시 사야 할 재료와 소용량 구매 권장 재료 안내
  - 레시피 노출·완료 이력 기반 개인화 랭킹 모델(CatBoost) 및 하이브리드 검색·리랭킹 튜닝
  - 레시피 분량 자동 제안: 분량 텍스트를 단위 변환하여 완료 확인 화면의 사용량 기본값 제안
  - 사용자 공유 레시피를 좋아요·완료 수 기준으로 추천 후보에 포함
- **AI 기능 확장**
  - AI 봇: 보유 재료와 레시피 DB를 근거로 한 요리·보관 질문 챗봇 (기존 RAG 구조 재사용)
  - 영상 레시피 요약: 요리 영상 링크를 입력하면 재료와 조리 순서를 요약하여 레시피로 저장
  - 주간 리포트 AI 코멘트: 지난주 이벤트를 바탕으로 낭비 원인과 다음 주 행동 제안
- **커뮤니티·게이미피케이션 확장**
  - 레시피 포크: 다른 사용자의 레시피를 가져와 내 방식으로 수정·저장, 원본 레시피 표시
  - 보관·손질 Q&A 게시판: 전문가 뱃지 계정이 답변하는 질문 게시판
  - 동네 랭킹: 활동 지역 기준 주간 냉장고 관리 점수 랭킹
  - 팔로우한 친구와 주간 점수 비교, 함께하는 주간 챌린지
  - 나눔 게시판 1:1 채팅(웹소켓), 위치 인증, 거래 후기·신뢰 점수
  - 레시피 퀴즈, 요리 수집형 미니게임 등 참여형 게이미피케이션
- **회원·알림 확장**
  - 소셜 로그인 (카카오 등), 토큰 만료·JWT 전환
  - 알림 종류별 설정, 반응 알림 묶음 표시, 웹소켓 기반 실시간 알림 (채팅과 함께 도입)
  - 비공개 계정 팔로우 요청·승인
- **소비기한 정확도 향상**
  - 포장지 촬영을 통한 실제 소비기한 날짜 인식
  - 기한 경과 확인 응답을 활용한 재료별 기준값 보정
- **입력 경로 확대**
  - 오프라인 마트 영수증 인식, 휴대폰 공유 버튼을 통한 캡처 전송
- **플랫폼 확장**
  - 모바일 화면 대응(반응형), 이후 사용성 검증을 거쳐 PWA 또는 모바일 앱으로 전환 검토 (푸시 알림, 공유 입력)
